# Executable Mode

`rapid-domain-mastery` 默认适合陈述性知识。若要扩展到编程等程序性技能，关键不是放弃 RDM，而是把 Phase 2 的验证器从“区分题”换成“可运行反馈”。

## 核心原则

1. **环境反馈即时可见**
   - 测试失败
   - 类型检查错误
   - lint 错误
   - 运行时错误

2. **教练反馈仍然延迟 reveal**
   - hint
   - 参考实现
   - 结构化讲解
   - 迁移点评

3. **学生仍然先交自己的产物**
   - patch
   - 源文件
   - 最小可执行程序

## 四阶段映射

### Phase 1

- 仍抽取心智模型
- 但每个节点要挂一个可动手探针

### Phase 2

- 从“区分题”切到“红灯任务”
- 给定失败测试、坏掉 fixture 或类型错误
- 学生先交补丁，环境即时运行检查
- 教练只在学生提交后提供 hint / 参考实现

### Phase 3

- 从口头迁移切到陌生约束下的最小程序

### Phase 4

- 固化成概念图 + 错题本 + 回归用例册

## 模式约束

- `assessment_mode=executable` 时，Phase 2 优先用任务和运行检查，而不是区分题。
- 即使在 executable 模式下，也保留 RDM 的学生先产出、教练后 reveal 的学习顺序。
